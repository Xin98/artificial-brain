# 美股日线投资模块运行手册

登录后访问 `/investment`（研究）、`/investment/accounts`（虚拟账户）和 `/investment/research`（回测）。`docker compose up --build` 同时启动数据库、迁移、API、Worker 和 Web。API/Worker 只检查 schema 11，不执行迁移；升级由独立 migrate 进程负责。

默认 `fixture` 使用虚构证券和合成价格、财报及新闻，页面标注“演示数据”。它证明系统行为，收益不能用来证明真实策略有效。第一版只有公开规则的 `multifactor-v1`，参考系统化量化研究流程；没有幻方私有模型、幻方服务接入或已训练的 Qlib 模型。

## 策略、账户及模拟规则

默认资金为 100,000 USD；初始自动交易关闭。创建股票池（最多 100 只）和策略生成不可变版本，账户绑定固定数据模式、feed 和 datasetVersion。模式/feed 变更需要新账户，不能拼接旧账本。美元金额与股数通过 API 返回十进制字符串；资金分别显示可用、预留、待结算、应收股息。

五组因子权重为动量 30%、趋势 20%、低波动 15%、估值 15%、质量 20%。排名使用同一可知时间的共同候选，至少 10 只满足全部条件；金融业、未知行业及缺失/过期财报会被排除。入场分数 70、退出 50，调仓带宽 2%，最多 10 只持仓。潜力是相对因子结果，风险独立显示；未知指标展示原因及原始事实来源。热点仅展示有权限的标题、摘要、来源链接，不改变交易评分。

| 风控项 | 默认上限/触发值 |
| --- | --- |
| 单只股票占净资产 | 10% |
| 同一行业占净资产 | 30% |
| 股票总占净资产 | 80% |
| 净资产峰值回撤暂停 | 15% |
| 持仓止损 | 10% |
| 普通单日双边成交额/净资产 | 20% |

用户只能收紧这些值。人工买单同样受风控与已结算现金约束；紧急减仓卖出可以越过普通换手限制。自动评估在纽约交易日收盘后至少 30 分钟进行，包含早收盘及夏令时；Worker 每 15 分钟检查待办。策略/股票池/风控配置变更从下一交易时段生效，启用或暂停立即记录。

不完整的行情或财报不会提前消耗当天的冻结评估；后续 tick 在数据齐备后继续。候选不足时仍保留有价格证据的止损、风险减仓和回撤暂停，并明确标注仅风控的结果。同步覆盖当前/待生效股票池、实际持仓及未完成订单，分批不超过 100 只。新闻源失败保留不可用标记，继续核心交易维护；状态无法持久化时仍报错。

拆股只调整生效时段之前的研究价格，不重复调整除权日原价。当前财报源没有可信的每股重述单位说明；TTM 跨越拆股或股份报告早于拆股时，PE、市值等单位敏感估值暂不可用，不能据此提高量化评分。可能保守地排除约一个 TTM 窗口，价格风险和明确的减仓保护继续可用。账户关联分析使用同一风控/调仓规则显示持仓减仓或暂停理由。

订单按下一交易日开盘原价模拟，整股、只做多，无杠杆。滑点买入 +10bps / 卖出 −10bps，手续费成交额 1bp、最低 $0.01；成交容量最多为此前 20 个交易日平均成交量的 1%，同账户同证券同交易日共享容量。开盘跳空可缩量，部分成交后取消余量。每天聚合 bar 到达后才确认原开盘成交；页面 `awaiting_bar` 表示已经进入不可撤销的有效时段，不能当作尚未买入且可自由撤销。

开盘前暂停会取消尚未生效订单并释放预留；开盘后暂停仍继续确认有效订单、公司行动和结算，不强制清仓。迟到 bar 只在原订单截止时间内确认原开盘，过期订单不移到后面的价格，也不因后来的数据复活。

卖出所得先进入待结算，按原成交日期的下一结算日释放。美股标准 T+1 规则见 [SEC FAQ](https://www.sec.gov/exams/educationhelpguidesfaqs/t1-faq)。本模块以该结算日纽约午夜作为虚拟可用资金边界，不声称代表任何券商实际入账时刻。交易日历与结算日历独立；缺少结算证明会阻断交易。拆股保持成本守恒，零碎股现金补偿需要明确单位；股息按除息前账本持仓确认应收，到支付日转现金。已应用行动发生修订或迟到拆股影响已成交库存时，阻断并要求核查，不猜测库存重算。

## 配置只读真实数据

真实源验收状态：**未配置、未对外调用验证**。本地 HTTP adapter 测试验证请求、身份、重试和解析，不等于实际订阅权限或生产数据完整性已验证。

| 变量 | 配置要求 |
| --- | --- |
| `INVESTMENT_DATA_MODE` | `fixture` 或 `alpaca_sec` |
| `INVESTMENT_ALPACA_FEED` | `iex` 或 `sip`；必须与账号订阅权限一致 |
| `INVESTMENT_ALPACA_KEY`, `INVESTMENT_ALPACA_SECRET` | 仅服务端注入，不写仓库或浏览器 |
| `INVESTMENT_SEC_USER_AGENT` | 真实产品名及运营联系邮箱，例如 `ExampleResearch operator@example.com` |
| `INVESTMENT_DATA_TIMEOUT` | 默认 `15s`，大于 0 且不超过 `60s` |
| `INVESTMENT_SETTLEMENT_CALENDAR_FILE` | API/Worker 都能读取的独立结算 JSON 文件绝对路径 |
| `INVESTMENT_NEWS_ENABLED` | 默认 `false`；运营确认访问及存储权限后才设 `true` |

API 与 Worker 必须使用一致配置。Compose 已传递变量；结算文件还需以本地 Compose override 的只读 volume 同时挂载到两个服务，例如 `/run/investment/settlement.json:ro`，环境变量取容器路径。不要将券商交易权限、账户号或下单服务接入本模块。适配器只发送 GET，读取 Alpaca assets/calendar/raw bars/corporate actions/news 与 SEC EDGAR 资料，没有券商订单接口。

IEX 只覆盖单一交易所，不能冒充全市场；SIP 权限和历史覆盖以订阅验证为准，参考 [Alpaca market data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) 和 [raw historical bars](https://docs.alpaca.markets/us/reference/stockbarsingle-1)。首次同步从研究页提交证券 ticker/稳定 ID 和日期范围，至少准备 201 日价格预热；需要基准时显式加入 SPY。后续自动同步股票池成员，不自动扩大为全部市场。SEC 请求标识运营者，单实例限制 2rps；多实例共用出口时还需运营方控制总请求频率，参见 [SEC fair access](https://www.sec.gov/filergroup/announcements-old/new-rate-control-limits)。

实源首次同步成功前保持 `not_configured`/`missing`，错误不会切换为合成数据。财报保存 accession、原始数值、单位及可知时间，修订不覆盖旧快照。日聚合数据保守地以次日纽约午夜可知，不能把当天尚未完成的数据用于收盘后的过早决策。供应商未证明历史公司行动最初公告时间时，真实历史回测会明确拒绝；不能将今天抓到的历史行动当成当时已知信息。

## 导入结算日历

JSON 只接受 `source`、`version`、`years`、`days`。下面是**格式片段，不是可用的完整年度日历**：

```json
{"source":"operator-verified official settlement calendar","version":"example-2026-v1","years":[2026],"days":["2026-01-02","2026-01-05"]}
```

`years` 必须唯一、连续，范围 2000–2100；`days` 必须唯一、有效且在声明年度内。文件必须列出这些年度的全部结算日，核对官方结算机构及银行假日，不能从股票交易日简单复制。加载器校验格式、范围和去重，无法从一份声明推断遗漏日期，完整性由运营核对。上线前核对当前年度、预热区间以及未来跨年交易的覆盖；将来源与版本存档。没有下一结算日或日期不在覆盖内时，保持交易阻断并补齐日历，不能改账户余额绕过。

## 恢复、并发及验证

所有写请求携带 `Idempotency-Key`。网络超时重试必须沿用原 key 和原 JSON；变更意图使用新 key。同 key 不同内容返回 409；账户/订单版本冲突先刷新配置再提交。数据库/服务错误返回 503，保留登录及表单；其他用户资源返回 404。

River 的 investment 队列并发 2，每任务最多 5 次尝试、10 分钟预算，指数退避从 500ms 封顶 60s。任务事务内写入队列和业务状态；账户锁、订单唯一 fill 与经济事件唯一键防止两实例和重启重复成交。数据刷新在账户事务外进行。重启 Worker 继续既有有效订单、应收、结算和任务；不要手工删除 ledger、fill 或 mutation_requests 来“重试”。用账户页的订单、评估、自动化事件与数据同步状态定位阻断原因；源配置故障先修复权限/日历，再提交新的同步意图。

回测为异步 `202 → queued/running/completed/failed`，最多 5 年、100 只池成员，与账户账本隔离，沿用同一撮合、费用、结算和公司行动规则。长区间可能超出任务预算，此时显示失败；缩短区间调查，不假装已有结果。SPY 基准同样包含整股、费用、现金及股息；缺失时给出原因。年化至少 252 日，Sharpe 至少 60 点且方差非零。当前池存在幸存者偏差，界面标注研究区间，不称为样本外验证。

完整本地验收使用 `make toolchain-check`、`make harness-test`、`make verify`、`make migration-test`、`make smoke-test`。数据库测试必须配置 `TEST_DATABASE_URL`；SKIP 不算数据库通过。smoke 复用隔离 fixture stack，两个临时用户经同源 Web 登录并创建账户/订单/回测；多日开盘和结算边界由 Go composition 注入时钟证明，无生产改时钟端点。

真实源验收表应另行填写运营者、feed/权限、日期范围、稳定证券 ID 与 CIK 对照、财报 accession、交易/结算日历版本、新闻权限、超时/限流结果及缺失数据处理。目前此表为空，所有投资收益仅为演示或未经外部验证的研究。
