# 美股日线投资模块设计

状态：书面设计已于 2026-10-07 获用户确认（回复“ok”），进入实现计划编写。本文件确认不等于尚未完成的实现计划已获批准；执行方式在计划交接时确定。

## 1. 目标与成功标准

在现有个人工作台增加投资模块，串联“行情与财报 → 量化信号 → 股票分析 → 风控 → 虚拟交易 → 绩效评估”。用户可以查看股票为何获得某个评分、建议为何生成、订单为何成交或被拒绝，以及策略相对基准的表现。

用户明确要求：参考幻方的量化方式；分析财报、热点及 PE 等常见指标，以量化结论为主要依据并用颜色标注风险和潜力；支持基于结果自动买卖，前期使用虚拟账户。用户确认：首版专注美股日线，每日评估，持仓数天至数周。

本设计提出的默认值：美元虚拟资金 100,000；仅做多普通股；不加杠杆；内置可解释多因子策略；自建日线模拟账本。这些是可修改的产品默认值，不是用户已经指定的资金量或风险偏好。策略收益不作为软件验收门槛，数据真实性、结果可重放、账本正确性及自动交易约束作为验收门槛。

领域语言见 [CONTEXT.md](../../../CONTEXT.md)。本文件批准后才编写任务级实现计划。

## 2. 路线决策与交付范围

| 路线                             | 优点                                              | 代价                             | 决策                                     |
| -------------------------------- | ------------------------------------------------- | -------------------------------- | ---------------------------------------- |
| Go 投资业务模块 + 可替换量化引擎 | 复用现有登录、数据库和 Worker；业务账本独立于模型 | 需要明确策略输出与执行的契约     | 采用；首版内置基线，后续独立接入 Qlib    |
| 全部自行实现量化研究与机器学习   | 控制完整、单一技术栈                              | 模型训练和研究工具成本大         | 首版只自建可解释基线，不自建深度学习平台 |
| 完全依赖第三方交易研究平台       | 接入较快                                          | 数据授权、费用、平台能力限制业务 | 行情来源可使用第三方，核心业务事实自有   |

幻方公开资料支持借鉴 AI 研究方向，不能据此声称获得其内部策略、选股接口或同等收益。Qlib 是可选的开放量化研究框架；首版交付不包括 Python 运行时、Qlib 安装、模型训练或 Qlib 生产接入，也不展示虚构的“AI 模型已接通”状态。首版量化能力由实际可执行的因子、回测和每日调仓提供。

首版是一条完整的日线闭环，按数据/研究、分析页面、虚拟执行三个交付段推进；每段保留可验证的业务结果，不拆成互相调用内部实现的多个业务上下文。

包含：自选股/股票池、数据同步状态、财务指标、新闻主题聚合、量化排名、分析建议、历史回测、账户/持仓/订单/资金流水、日线自动评估和模拟撮合、风控与审计、基准对比。

暂不包含：实盘券商下单、分钟级交易、盘前盘后、做空、融资、期权、碎股、实时订单簿、大模型自行决定交易、全市场因子挖掘、投资对话指令、投资数据导入导出。ETF 首版仅作为可配置基准，默认 SPY，不进入股票自动选股池。

## 3. 架构与模块接口

保持 Go 模块化单体、Next.js 和 PostgreSQL，遵守 `inbound adapter → application → domain`，应用层只依赖自己定义的 ports，具体适配器由 `cmd/api`、`cmd/worker` 组合。Platform 不导入 Investment，既有业务模块不导入 Investment 内部实现。

业务实现位置：`backend/internal/modules/investment/{domain,application,adapters}`；Web 功能位置：`apps/web/src/features/investment`，路由 `/investment` 及子页面。复用已有身份与 workspace/owner 作用域、事务执行器、错误 envelope 和 River 持久化任务，不增加 Go 或 Web 依赖。

Investment 的外部业务接口集中在账户/股票池配置、数据状态查询、策略评估、历史回测、订单提交/取消、自动交易启停和结果查询。HTTP 和 Worker 调用同一应用命令；因子计算、模拟撮合及账本规则留在模块内部。

内部模块职责：Data 整理来源与截止时间；Research 计算信号和实验；Analysis 生成证据明确的建议；Portfolio 管理订单、预留、成交和账本。它们属于同一 Investment 上下文，不形成平台业务包。

必要 seams：`MarketDataPort`（证券资料、交易日历、日线、公司行动）、`FinancialDataPort`（按申报版本取事实）、`NewsPort`（按证券取可知新闻）、`InvestmentStore`、`UnitOfWork`、任务调度接口。每个外部数据 seam 首版有真实 HTTP 适配器和固定 fixture 适配器，用于实际开发/CI差异；时间由调用方注入。Research 的版本化输入/输出作为模块内部接口，不在首版增加无人使用的远程引擎服务。

未来 Qlib 接入需在独立设计中落实训练数据、模型验证、部署和资源预算；输出至少携带 instrument、asOf、strategyVersion、datasetVersion、score、rank、factorEvidence、qualityFlags。它生成信号，不能绕过现有风控或直接修改账户账本。

## 4. 数据来源与工作模式

| 数据                                    | 首版来源                                       | 约束                                                                    |
| --------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------- |
| 美股日线、证券资料、交易日历、拆股/分红 | Alpaca Market Data / Trading 的只读端点        | 凭据只在服务端；按账户权限验证每种端点；不使用交易下单端点              |
| 财报与历史申报                          | SEC EDGAR submissions、companyfacts 和申报文件 | 以申报 accession 和公开时间识别版本；遵守访问政策；非统一口径不强行比较 |
| 新闻与热点                              | Alpaca News 候选适配器                         | 独立验证权限；不可用时显示新闻未连接；不得伪装为无新闻                  |
| CI / 离线演示                           | 版本化固定 fixtures                            | 明确展示“演示数据”，账户与外部行情模式隔离                              |

真实数据模式要求操作者配置自己的数据凭据。无凭据仍可完成离线演示与验收，不自动注册账户或购买订阅。免费 Alpaca 实时股票行情主要覆盖 IEX；界面始终注明 feed、覆盖、延迟和最近成功同步时间，不称为全市场实时行情。Provider、feed 或数据模式变更后创建新数据集版本，不能静默拼接实验曲线。

持久化字段至少包括 `source`、`sourceRecordId`、`instrumentId`、`effectiveAt`、`availableAt`、`ingestedAt`、`datasetVersion`、`coverageFlags`。财报另外保存 accession、报告期、单位、币种、修订版本和用于计算的原始事实引用。新闻保存文章标识、证券关联、发布时间和链接；首版保存标题、摘要与主题，不复制完整付费文章。

历史选择以 `availableAt <= asOf` 为条件。只有发布日期、没有精确发布时间的财报，保守地从该日期后的下一交易日可用。修订财报不能覆盖先前快照，也不能提前用于历史评估；不能用最新 companyfacts 汇总值直接回填历史。季度、年累计和全年事实先还原为不重叠季度，四季度 TTM 不重复求和；不能明确还原则返回缺失及原因。

以未复权价格记录成交，因子使用在相应截止时间已发生的拆股调整序列；分红进入公司行动与账户收益，不在成交价格中再次扣除。公司行动历史不完整时阻止跨该事件的可信回测和自动模拟执行，显示数据修复状态。

股票池首版为用户显式配置、版本化的普通股集合，最多 100 只。演示模式提供固定 30 只虚构证券及相应数据，真实模式初始为空并引导设置。证券标识不只依赖 ticker，保留 CIK、交易所及 ticker 变更。历史股票池若来自当前列表，结果必须标注“固定股票池实验，包含幸存者偏差”，不能宣称历史全市场表现；没有退市结算或可靠终值的实验不能生成完整绩效结论。

## 5. 因子与策略计算

首版发布一个默认策略 `multifactor-v1`，参数修改产生新的不可变策略版本。每日收盘后评估一次，不做盘中追涨，也不宣称模型预测价格。

| 因子组   | 定义                                                               | 权重 |
| -------- | ------------------------------------------------------------------ | ---- |
| 动量     | `close[d]/close[d-63]-1` 与 `close[d]/close[d-126]-1` 的百分位均值 | 30%  |
| 趋势     | `close[d]/SMA50-1` 与 `SMA50/SMA200-1` 的百分位均值                | 20%  |
| 低波动   | 最近 20 个有效日收益样本标准差，取反向百分位                       | 15%  |
| 估值     | TTM 净利润/市值、TTM 自由现金流/市值的百分位均值                   | 15%  |
| 财务质量 | TTM 净利润/期初期末平均权益、TTM经营现金流/TTM营收的百分位均值     | 20%  |

日收益按当时拆股调整后的收盘价计算；波动率展示值年化乘 `sqrt(252)`，因子排序使用同一原始标准差。SMA 使用对应数量的有效交易日，至少需要 201 根日线，不以自然日或缺失补零替代。TTM 至少有四个可解释的不重叠季度。自由现金流为经营现金流减去按正支出归一化的资本开支；单位/币种不一致禁止计算。

对本次共同合格股票池中每个子因子做排序；并列用平均名次，百分位为 `(平均名次-1)/(N-1)*100`，方向统一为越高越有利。潜力评分是因子组百分位的固定加权和，保留一位小数，不是盈利概率。候选证券须具备全部必需因子、正市值、正权益、正营收、有效行业组和价格覆盖；不得静默改变权重填补缺失。负净利润或负自由现金流可以产生有效但较低的收益率因子；PE 在盈利非正时展示“不适用”。

至少 10 只合格证券才形成可用于自动选股的排名，否则产生 `insufficient_universe`，展示具体缺失原因并停止新买单；仍可显示个股已有指标，保留明确触发的减仓规则。首版不把金融行业与普通企业的现金流/质量因子混用：按版本化 SEC SIC 映射识别行业，金融行业和无法映射的股票仅供分析，不进入该默认策略的自动候选池。这是本策略适用范围，不是金融股风险结论。

因子、输入快照及排名必须同次提交为 `EvaluationRun`。确定性规则：数据集、股票池、截止时间、参数一致时，信号、排序及建议一致；最终分数并列以 instrumentId 排序。默认权重是待验证的研究假设，界面不称为经过收益验证的最优配置。

## 6. 分析、热点与展示

个股页面包含量化因子贡献、财报事实、估值、价格指标、相关新闻、潜力/风险及账户关联建议。首版指标：PE-TTM、PB、市值、营收/净利润同比、经营现金流、自由现金流、资产负债率、ROE、SMA20/50/200、RSI14、20 日波动率、252 日窗口内最大回撤、20 日平均成交额。PE 使用同一截止时间价格和已公开 TTM 稀释 EPS；EPS/股数与拆股单位必须一致。资产、权益、EPS等分母非正时相关比率返回不适用，不展示无穷大或以零代替。

同比使用可比报告期且分母为正，否则说明不可比较。RSI14 使用 Wilder 平滑，首次用 14 个日变化初始化；无涨无跌为 50，只有上涨为 100，只有下跌为 0。回撤为截止日之前最多 252 个有效交易日的峰谷最大下降比例，少于完整窗口注明实际窗口。

热点采用证券绑定新闻的近 7 个自然日主题计数与最近 24 小时变化，使用版本化关键词分类；显示原始标题、来源、发布时间和链接。新闻摘要只解释文本，不编造传闻真实性、事件概率或已接入的大模型能力。首版热点不进入自动订单评分或买卖触发；新闻源离线不阻止完整财报/行情策略运行，但必须可见。

股票风险分级与潜力独立：年化波动率 >60% 或窗口最大回撤 >35% 为高；否则波动率 >30% 或回撤 >20% 为中；其余为低。阈值是产品默认研究规则，不是投资认证。指标覆盖不足、行业未知或价格过期展示“风险未知/数据不足”，不能显示低风险。

潜力：评分 >=70 显示绿色“较高”，50–69.9 显示黄色“观察”，<50 显示灰色“较弱”。风险：红色“高”、黄色“中”、低风险显示中性文字；未知为灰色并解释。收益涨跌另有独立图例，任何颜色都有文字和可访问名称。可同时出现“潜力较高 / 风险高”。

建议是确定性结构：行动、有效截止时间、策略/数据版本、因子证据、财务说明、风险限制及无法判断的项目。对持仓不足/过期数据显示观察；持仓低分/触发止损或风险限额可建议减仓；买入建议必须同时满足合格排名和账户新买单约束。单独查看股票而未选择账户时仅给研究倾向，不伪装成已完成账户风控。

## 7. 账户、自动调仓与风控

首版每个用户/workspace 可创建多个美元虚拟账户，每个账户绑定一种数据模式、一个策略版本和一个股票池版本。金额用固定精度十进制/整数最小单位，计算价格保留六位小数、账本美元金额保留分、费用向上取整到分；禁止二进制浮点保存资金。数量为整数股，平均成本包含买入费用，卖出已实现盈亏按加权平均成本计算。

自动交易默认关闭。用户首次启用后，系统按规则持续运行，无需逐笔确认；启用记录保存配置、用户及时间。单账户一次只允许一个有效评估/调仓批次。用户修改参数产生下一交易日生效的配置版本并取消旧配置未成交买单，不修改历史事实。

| 默认约束                             | 行为                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------- |
| 单股目标权重上限 10%                 | 新买单按成交假设重新校验，不足整股则跳过                                |
| 同行业组目标权重上限 30%             | 未知行业不得自动新买；行业为 SEC SIC 映射，不宣称 GICS                  |
| 总股票目标仓位上限 80%               | 保留至少 20% 目标现金；限制作用于订单后预测敞口                         |
| 账户最大回撤阈值 15%                 | 暂停自动交易并取消尚未到生效时刻的订单；保留持仓，要求用户处理/重新启用 |
| 持仓收盘价较费用后平均成本下降 >=10% | 生成次日卖出订单；不能保证跳空时实际亏损不超过 10%                      |
| 单日换手上限 20% NAV                 | 非紧急买卖绝对成交名义额之和；止损/减风险卖出可越过并记录原因           |

风控同时作用于自动和手动订单。卖出优先但卖出未结算款不用于当天买入。现金、预留资金、持仓、预留股数都必须非负；不允许裸卖、透支或多条订单重复消费同一余额。市场波动可使既有持仓超限，下一次评估禁止加仓并按规则减仓，不承诺实时维持硬比例。

调仓先卖出止损及评分 <50 的持仓、减去超限部分；再从风险非高、评分 >=70 的合格排名取最多 10 只，以每只最多 10% NAV、总共最多 80% NAV形成候选目标。按排名顺序经过行业/现金/换手限制，未通过的额度留作现金。已有持仓评分处于 50–69.9 时不主动清仓、不加仓，其占用额度先从 80% 上限扣除；目标权重差 <2 个百分点不生成普通调仓订单。减风险与止损规则优先于这条缓冲规则。

暂停原子地取消尚未到目标开盘时刻的订单、释放对应预留并阻止新的自动批次；已到生效时刻的订单只等待日线确认，暂停不能事后撤回，界面提示其可能继续入账。已经提交成功的成交不会被撤回。暂停后的手动订单需主动提交，仍经过风控。行情过期停止新的自动订单，只允许已有生效订单在规定窗口内依据其目标日有效日线完成确认或到期；财报缺失禁止依赖该因子的新增仓位，不凭空生成减仓价格。

## 8. 日线撮合、结算与公司行动

默认执行模型 `next-session-open-v1`：交易日 D 收盘后可用信息生成订单，指定 D+1 常规交易时段的开盘价模拟成交。首版不订阅分钟数据；D+1 日线到达后才能完成撮合记账，界面显示“等待下一交易日日线”，分别记录 `effectiveAt`（D+1 开盘）与 `recordedAt`（实际入账时间）。这不是实时券商 Paper Trading，不声称在开盘时已真实获得成交确认。

手动买卖首版也是整数股、日线市价模拟订单，按订单提交后的下一常规交易日开盘撮合；不提供限价、止损挂单或盘中成交。到达目标开盘时刻，订单进入 `awaiting_bar`，取消/暂停命令按服务端时钟先确认这一转换，即使 Worker 暂未运行也不能事后取消。未成交订单只对指定下一交易日有效，缺失/停牌无法撮合则到期并释放预留，不使用后来某一天的价格补成交。源数据延迟最多等待到目标交易日后的下一交易日收盘；之后标记 `expired_data_unavailable`，迟到数据不能恢复已过期订单。

模拟价格为未复权开盘价，买入增加 10bps、卖出减少 10bps 滑点；手续费为名义额 1bps、最低 $0.01。它们是可配置的模拟假设，不能称为某券商实际费用。买单提交时按最新有效收盘价及费用假设预留；开盘跳空使预留不足时，仅在原预留内减少整股成交量，不能额外占用别的订单预留。卖单预留数量。

模拟容量最多为截至订单生成时最近 20 个有效日平均成交量的 1%，向下取整；该容量由同账户同证券同目标交易日的全部成交共享，不得通过拆单绕过。若只足够部分成交，原子记录成交部分，取消余量并释放余量预留。撮合使用开盘价，不读取 D+1 收盘价、最高价、最低价、全天成交量来决定是否成交或交易数量。

账户现金科目固定为 `availableCash`（已结算且未预留）、`reservedCash`（买单预留）、`unsettledReceivables`（卖出待结算款）和 `dividendReceivables`（分红应收）。预留仅从 available 划转到 reserved，成交从 reserved 扣除金额与费用，余量退回 available；卖出净收入进入 unsettled，并按结算日历在下一结算日开始划转到 available。NAV 为上述四项之和加持仓市值，不重复计算预留。初始资金进入 available，分红入账只从 dividendReceivables 划转到 available。暂停和重试不能改变原结算日期；晚到成交按原生效日期结算，但生成过去订单时不能使用后来补记的资金。

拆股按事件生效日、该日开盘状态转换前调整持仓数量及平均成本，取消受影响 pending 订单以便下一次评估重新规划；事件晚到而订单已进入 awaiting_bar 时，冻结该证券执行，按原开盘前事件规则完成核对并记明公司行动取消原因，不以拆股后价格执行旧数量。非整数余股需要来源提供现金替代金额，否则暂停该证券撮合而不猜价格。分红以除息资格快照登记应收、支付日入账，仅重放一次；分红应收纳入 NAV，支付只做科目划转。缺少日期或币种/金额时标记不完整、阻止相关执行/可信绩效。退市、并购等未支持事件不伪造清算成交，冻结相关自动交易和完整绩效结论。

## 9. 持久化、幂等与恢复

新增 `investment` schema；只追加新迁移，当前 schema version 为 10，设计预期使用下一可用迁移编号（当前为 011），实现前重新确认。保留迁移 001–010 字节不变。API/Worker 只验证 schema，只有 migrate 命令执行迁移。

事实实体：accounts、universe_versions/members、strategy_versions、data_snapshots、instrument_facts、price_bars、financial_facts、news_items、corporate_actions、evaluation_runs/signals、recommendations、backtest_runs、orders、fills、ledger_entries、nav_snapshots、automation_events。具体表拆分与索引在实现计划中按访问模式落实，不能把账户业务事实放入 `public.instance_meta`。数据来源事实可共享缓存，账户/股票池/实验/订单/流水始终按 workspace/owner 隔离。

订单状态：`pending → awaiting_bar → filled | partially_filled_cancelled | expired | rejected`；尚未到生效时刻的 `pending` 可取消；awaiting_bar 只能因核对出开盘前公司行动而取消，不能由用户事后撤单。终态不可反转。提交失败的风控尝试有审计记录，不预留资金。版本冲突返回 409，不静默覆盖。

同一账户、交易日、策略版本、数据模式的自动评估采用唯一业务键；输入快照冻结后重试不可切换到新数据。API 修改操作要求 `Idempotency-Key`，同 owner/路由/key 且相同请求返回原结果，不同请求返回 409。订单成交、科目流水、仓位更新、预留释放和任务结果在同一数据库事务提交；fill、公司行动、结算迁移都有唯一事实键。

River 只负责投递与重试，业务状态保存在 Investment。外部读请求不持有数据库事务；账户变更在事务内锁定账户与订单，固定 instrumentId 顺序处理持仓避免死锁。Worker 在提交后崩溃，重试只读取已经成功的结果，不重复买卖；失败超过重试预算进入可见失败状态。多个 Worker 竞争同一账户时仅一个能提交。

## 10. 调度、错误与可观测性

交易决策时区固定 `America/New_York`，存储 UTC，浏览器可显示用户时区并附美东交易日。交易日历从 Alpaca 只读接口同步；结算日历以操作者导入、附来源和年份的美国证券结算日历为准，离线验收提供固定日历，不把交易所开市日自动等同结算日。真实数据模式未配置覆盖所需年份的结算日历时不能启用自动交易，界面明确提示。周末、休市、提前收盘与夏令时都由日历决定，不用工作日字符串推算。

Worker 复用 River，每 15 分钟发起轻量补偿检查。交易日收盘后至少 30 分钟且日线已可用才建立评估批次；先完成可处理的前次撮合/结算/公司行动，再估值和评估当前日。账户若还有上一执行日未决的 awaiting_bar 或未确认公司行动，只展示最后有效估值并暂停新评估订单，不能根据暂时缺失的持仓进行再买入。错过调度后，只在下一交易时段开盘前补做该日决策；超过截止时间的评估仅可供研究，不能为已过去开盘时间补发持续模拟订单。此前已存在的订单可以依据第 8 节的迟到数据窗口补记成交。

429/可重试网络故障按 Retry-After 或有界退避处理；认证失败不无限重试。价格数据须覆盖上一已完成交易日；默认策略要求最新可知财报的报告期末距评估日不超过 180 个自然日，这不意味着构成 TTM 的较早季度失效。页面显示证券级数据缺口，系统数据故障不被当成账户余额零或没有持仓。

稳定错误 envelope 沿用 `{code,message,correlationId}`，新增业务码至少包括 `data_not_configured`、`data_stale`、`insufficient_universe`、`factor_unavailable`、`corporate_action_incomplete`、`insufficient_settled_cash`、`risk_limit_exceeded`、`automation_paused`、`version_conflict`、`idempotency_conflict`。越权资源统一 404，不泄露其他用户账户。

日志记录 correlationId、runId、accountId、策略/数据版本、拒绝原因、同步耗时、任务重试与撮合结果；不记录凭据或完整原始新闻内容。运营查询显示最近同步/评估/撮合、失败任务、暂停原因与数据质量，不扩大未认证系统健康接口的数据暴露。

## 11. Web 与业务契约

`/investment` 提供账户概览、数据连接状态、股票排名、潜力/风险过滤和自动交易状态；`/investment/stocks/[instrumentId]` 展示个股证据；`/investment/accounts/[accountId]` 展示持仓、订单、资金流水及自动交易配置；`/investment/research` 创建和查看回测。复用现有中文导航与 session gate；新增样式优先局限于功能，必要的 globals.css 改动进入 yellow register。

图表展示策略与基准曲线、回撤、持仓分布。用现有 React 和 SVG/HTML 实现，不引入图表依赖。每项结果显示数据模式、截止时间、策略版本和数据质量；演示标记始终可见，新闻不可用和财务缺失分别有状态、原因与重试入口。

新增 `/api/v1/investment` 前缀，全部需要 session：

- `GET /data-status`、`POST /data-sync`：只读连接/覆盖状态及幂等增量同步请求；凭据由部署配置提供，不通过浏览器返回。
- `GET /instruments`、`GET /instruments/{id}/analysis`：搜索、事实及分析；后者可指定 accountId，指定时必须校验所有权。
- `GET|POST /universes`、`POST /universes/{id}/versions`：股票池查询、创建及不可变成员版本。
- `GET /strategies`、`POST /strategies/{id}/versions`：已支持策略及不可变参数版本。
- `GET|POST /accounts`、`GET /accounts/{id}`、`GET /accounts/{id}/positions`、`GET /accounts/{id}/ledger`、`GET /accounts/{id}/performance`。
- `GET|POST /accounts/{id}/orders`、`POST /accounts/{id}/orders/{orderId}/cancel`：手动订单与历史查询。
- `PUT /accounts/{id}/automation`、`POST /accounts/{id}/evaluations`、`GET /accounts/{id}/evaluations`：配置/启停、研究评估请求与历史。手动评估不能绕过一次日线自动批次限制或自动交易关闭状态。
- `GET|POST /backtests`、`GET /backtests/{id}`：异步创建和查看独立历史实验，返回 202/runId 并查询状态。

所有列表用稳定游标分页，默认 25、上限 100。金额/数量/价格使用十进制字符串，风险/评分/质量状态分开返回；不能用一项“综合推荐分”隐藏风险。修改自动配置校验 expectedVersion；订单及实验等资源读取校验 owner/workspace。

## 12. 回测和绩效

历史回测与持续模拟账户不共享余额、订单或持仓，只共享同版本策略、风控、撮合和账本规则。任务冻结股票池、数据快照、策略、费用/滑点、日期范围及基准。至少有 201 根预热日线且实验执行区间不少于 20 个交易日；缺少必要历史公开时间、公司行动或退市终值时拒绝生成可信完整实验，不填充虚构收益。

回测逐日按“结算/公司行动 → 执行此前已生成订单 → 收盘估值 → 生成下一交易日订单”重放。绩效使用包含分红与费用的 NAV，现金收益首版为零，明确披露。默认初始资金 100,000 美元，首版回测/账户都不支持外部入金、提现或重置已有账本；用户需要重新实验时创建新回测或新账户。

展示累计收益、最大回撤、换手率、费用/滑点假设、与 SPY 同区间总回报对比。累计收益为期末 NAV/初始 NAV-1；年化收益仅在至少 252 个有效交易日时显示，按 `(期末/初始)^(252/N)-1`；Sharpe 使用日 NAV 收益、零无风险利率和样本标准差，至少 60 个日收益，标准差为零则不适用。换手率为区间买卖绝对名义额之和/区间每日 NAV 均值，注明双边口径。

SPY 基准用同资金在第一个执行交易日开盘买入并持有、处理拆股/分红，扣同套费用/滑点，余款保留现金；不与价格指数或未计分红曲线混比。基准数据不完整时单独显示无法比较，不伪造超额收益。短期窗口不外推年化收益；盈利“胜率”因部分卖出分组口径复杂首版不展示。

首版没有模型训练；对调参研究，结果明确标注研究期和独立检验期，禁止用全历史最优参数包装样本外表现。后续接入机器学习时，必须额外定义按时间划分的训练/验证/测试和滚动验证，不沿用当前实验截图宣称训练有效。
